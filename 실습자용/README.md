# SAP Generative AI Hub 핸즈온 — 4시간 (실습자용)

SAP AI Core의 **Generative AI Hub**를 **Python SDK**로 다루는 4시간 실습입니다.
LLM 호출 → 임베딩 → Orchestration → Document Grounding → RAG → 메모리 챗봇까지 **코딩 중심**으로 진행합니다.

> 기반 자료: [SAP-samples/generative-ai-codejam](https://github.com/SAP-samples/generative-ai-codejam)

---

## 🤔 Generative AI Hub가 뭔가요? (한 문단 요약)

여러 회사(OpenAI, Anthropic, Google …)의 LLM을 **각각 따로 계약·연동하지 않고**, SAP AI Core 안에서 **하나의 SDK로 통일해서** 쓰게 해주는 서비스입니다. 핵심 장점 세 가지만 기억하세요.

1. **모델 교체가 코드 한 줄** — `gpt-5.6-sol` → `anthropic--claude-4.6-sonnet` 로 이름만 바꾸면 됩니다.
2. **Orchestration** — 프롬프트 템플릿·콘텐츠 필터·개인정보 마스킹·문서 그라운딩을 **선언형 설정 하나**로 묶습니다.
3. **Document Grounding** — RAG(문서 기반 답변)를 직접 구현하지 않고 **관리형**으로 씁니다.

이 네 시간 동안 위 세 가지를 **직접 코드로** 경험합니다.

---

## 이 과정의 전제

- **단일 공유 AI Core**: 강사가 구성한 **하나의 AI Core 인스턴스**를 전원이 공유합니다. Orchestration·LLM·임베딩 배포는 **이미 되어 있고**, 여러분은 배포를 만들 필요가 없습니다.
- **SDK 중심**: 실습은 Launchpad 클릭이 아니라 **노트북에서 SDK 코드를 작성/실행**하는 방식입니다. (UI 실습은 보너스/데모로만)
- 여러분이 할 일은 **강사가 공유한 연결 값**을 `variables.py` 에 넣고, 노트북 셀을 실행하며 코드를 바꿔보는 것입니다.

> 💡 **코딩이 처음이어도 괜찮습니다.** 모든 코드 셀은 그대로 복사·실행하면 동작하도록 되어 있습니다. 실습의 진짜 재미는 **"직접 바꿔보기"** 에서 값 하나를 바꿔보고 결과가 어떻게 달라지는지 관찰하는 데 있습니다.

## 진행 방식

- 각 모듈 파일을 **순서대로** 엽니다.
- 흐름: **강사 설명 → 코드를 노트북 셀에 붙여넣고 실행 → "직접 바꿔보기"로 변형 실습 → 체크포인트로 확인**.
- 공유 인스턴스이므로 아래 **주의**를 지켜주세요.

### ⚠️ 공유 인스턴스 주의

- 모두 **같은 배포·그라운딩 저장소를 읽기만** 하므로 안전합니다. 쓰기(수집)는 강사가 사전 처리합니다.
- 모두가 동시에 호출하면 가끔 느리거나 제한될 수 있습니다. 실패하면 **잠시 후 재시도**하세요.
- `documents/` 등 공용 리소스는 **삭제·변경하지 마세요**.

| --- | --- | --- | --- |
| 0:00–0:15 | 0. 연결 | 공유 값 입력 + 연결 확인 | SDK |

| 1:20–2:05 | 3. Orchestration + 필터 + 마스킹 | 모듈 파이프라인, 입출력 필터, PII 마스킹 | SDK |
| 2:05–2:15 | ☕ 휴식 | | |

## 📚 전체 흐름 한눈에 보기

```
[0] 연결 확인
      │  공유 AI Core에 SDK로 접속
      ▼
[1] LLM 프롬프트 ─── 모델에 질문/답변. role·환각·멀티모달 체험
      │
      ▼
[2] 임베딩 ─────── 텍스트 → 벡터. "의미의 가까움"을 숫자로 (RAG의 기초)
      │
      ▼
[3] Orchestration ─ 템플릿+필터+마스킹을 설정 하나로 묶기
      │
      ▼
[4] 공개 그라운딩 ── help.sap.com 문서로 근거 기반 답변 (환각 ↓)
      │
      ▼
[5] 내 문서 그라운딩 ─ 내 벡터 저장소로 소스만 교체
      │
      ▼
[6] 메모리 챗봇 ──── 대화 history를 기억
      │
      ▼
[7] 마무리 & 보너스
```

> **왜 이 순서인가?** 1에서 "모델은 때로 지어낸다(환각)"는 문제를 겪고, 2에서 그 해결의 재료(임베딩)를 배우고, 3~5에서 Orchestration·그라운딩으로 **환각을 실제로 줄이는** 흐름입니다.

## 시작 전 체크 (대부분 강사가 공유)

- [ ] BAS dev space + 저장소 clone + `pip install -r requirements.txt`
- [ ] 강사가 준 **연결 값**을 `variables.py` 에 입력
  - `RESOURCE_GROUP` (공유 리소스 그룹)
  - `LLM_DEPLOYMENT_ID`, `EMBEDDING_DEPLOYMENT_ID`
  - `AICORE_ORCHESTRATION_DEPLOYMENT_URL`
  - `GROUNDING_REPOSITORY_ID` → 내 문서 그라운딩용 저장소 id (강사 공유, 모듈 5)
- [ ] 강사가 준 **AI Core 자격증명**을 `~/.aicore/config.json` 또는 환경변수로 설정
- [ ] 모듈 0의 연결 확인 셀 통과

## 🧰 자주 쓰는 용어 미리보기

| 용어 | 쉬운 설명 |
| --- | --- |
| **LLM** | 대형 언어 모델. 질문을 넣으면 답을 생성하는 모델 (예: GPT, Claude) |
| **배포(Deployment)** | AI Core에서 특정 모델을 "실행 중" 상태로 올려둔 것. 이걸 통해 호출합니다 |
| **임베딩(Embedding)** | 텍스트를 의미를 담은 **숫자 벡터**로 바꾼 것 |
| **환각(Hallucination)** | 모델이 모르는 걸 **그럴듯하게 지어내는** 현상 |
| **RAG** | 질문과 관련된 문서를 **먼저 찾아** 프롬프트에 넣어주는 기법 (환각 ↓) |
| **그라운딩(Grounding)** | RAG를 SAP가 관리형으로 제공하는 것. 저장소만 지정하면 검색·주입을 대신 해줌 |
| **Orchestration** | 템플릿·필터·마스킹·그라운딩을 **설정 하나로 조립**하는 모듈 |
| **PII 마스킹** | 이름·이메일 등 개인정보를 모델에 보내기 전에 **가리는** 것 |
