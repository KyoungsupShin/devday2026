⌂ 인덱스캡스톤-설계도

캡스톤 에이전트 — 개발 설계도

AI Core 기반 고객사 Agent — SAP AI Core Orchestration을 중심으로, 고정형 + 목표지향 자율형 에이전트를 구현한다.

작성일: 2026-10-11 · 스택: Python(gen_ai_hub orchestration_v2) + LangGraph + CAP + React

1. 설계 원칙

  1. 아는 건 코드로, 모르는(외부) 건 에이전트로 — 내부 데이터·고정 규칙은 결정론적 코드, 외부/가변 상황은 Agent Loop.
  2. HOW가 아니라 WHAT — 고정형은 단계를 지시, 자율형은 목표(target)만 주면 스스로 경로를 설계.
  3. Orchestration을 중심(두뇌)으로 — 모든 LLM 추론이 Orchestration을 거쳐 데이터 마스킹·콘텐츠 필터·그라운딩·툴콜이 일괄 적용된다. (거버넌스가 공짜)

2. 핵심 기술 결정 (실측 확인됨)

결정 근거
Orchestration이 에이전트 두뇌 orchestration_v2에 tools 모듈 존재 — Template(tools=[...]) 로 function calling 지원 (⚠️ Launchpad UI엔 미노출, SDK로만)
구조화 출력 Template(response_format=...) 지원 (json_schema)
루프 제어 = LangGraph tool_call 유무로 라우팅/반복/종료
기본 모델 = gpt-5.6-sol 테넌트 배포됨 (단 temperature=0 미지원 → 생략)
외부 데이터 = 환율 API open.er-api.com (무료·무키)

Orchestration 기능 매트릭스 (UI vs SDK) — 공식 기능표 + 라이브 실측 일치:

기능 AI Launchpad UI SAP Cloud SDK for AI
Templating / Content Filtering / Data Masking / Grounding / Translation ✅ ✅
Streaming ❌ ✅
Tool Calling ❌ ✅
Multimodal (이미지 입력) ❌ ✅
Response Format 제어 ❌ ✅

→ Tool Calling·Streaming·Multimodal·Response Format은 SDK 전용. 그래서 이 캡스톤은 SDK 기반이며, UI에 tool 추가 메뉴가 없는 것은 정상이다.

라이브 검증 완료 (2026-10-11, 이 테넌트): - Orchestration이 tool_calls를 네이티브 출력 (gpt-5.6-sol, gpt-4o) - 멀티턴 agent loop 동작: tool_call → 우리 코드 실행 → ToolChatMessage로 되먹임 → 다음 턴 → 최종 답 - 내부(재고) + 외부(환율) 데이터를 함께 사용해 스스로 발주 판단 - 피드백 배선: AssistantMessage(tool_calls=...) + ToolChatMessage(tool_call_id, content) 를 run(history=...) 로 전달 (자동실행 없음 → 루프는 우리 코드)

4. 두 모드 대비

모드 A · 고정형 모드 B · 목표지향 자율형
지시 HOW (고정 흐름) WHAT (목표치만)
도구 정해진 순서 자유 선택·반복
외부 변화 대응 불가 스스로 경로 변경
Orchestration 고정 파이프라인(마스킹/필터/그라운딩) 두뇌(tools) + 마스킹/필터/그라운딩
예시 "재고<임계 → 고정수량 발주" "품절0·비용최소·예산1천만원" → 알아서

5. 시나리오 데이터 흐름 (재고/발주)

[기존 로직 — 결정론적 코드]
  CAP 재고 조회 → 안전재고 미달 품목 산출            ← AI 불필요

[Agent Loop — 목표: "품절 없이 비용 최소화, 예산 1천만원"]
  Orchestration(두뇌): get_inventory → 부족 품목 파악
     → get_fx(USD,KRW) 관찰: "원화 약세"                ← 외부
     → search_policy("MOQ/할인") 관찰: "B 500개↑ 10%↓"  ← 그라운딩
     → 추론: 예산 내 최적 조합 계산
     → 결론: "A 최소만, B 500개(할인), C 보류" + 발주 초안
  ※ 매 추론이 Orchestration 경유 → PII 마스킹·유해 필터 자동 적용

6. 컴포넌트 설계 (핵심 코드 골격 — 검증된 API)

도구 정의 + Orchestration에 부착

from gen_ai_hub.orchestration_v2.models.tools import FunctionTool, FunctionObject
from gen_ai_hub.orchestration_v2.models.template import Template, PromptTemplatingModuleConfig
from gen_ai_hub.orchestration_v2.models.config import ModuleConfig, OrchestrationConfig
from gen_ai_hub.orchestration_v2.models.data_masking import MaskingModuleConfig, ...
from gen_ai_hub.orchestration_v2.models.document_grounding import GroundingModuleConfig, ...

get_fx_tool = FunctionTool(function=FunctionObject(
    name="get_fx", description="현재 환율 조회",
    parameters={"type":"object","properties":{"base":{"type":"string"},"quote":{"type":"string"}}},
    function=get_fx))        # 실제 파이썬 함수 연결

template = Template(
    template=[SystemMessage(...), UserMessage("{{?goal}}")],
    tools=[get_fx_tool, get_inventory_tool, search_policy_tool],   # ← 두뇌가 쓸 도구
)
config = OrchestrationConfig(modules=ModuleConfig(
    prompt_templating=PromptTemplatingModuleConfig(prompt=template, model=LLMModelDetails(name="gpt-5.6-sol")),
    masking=masking, filtering=filtering,   # ← 거버넌스 (충분히 사용)
))

루프 (LangGraph 커스텀 노드 또는 핸드롤)

while not done and i < MAX:
    resp = orchestration.run(goal + 관찰들)   # ← 두뇌 = Orchestration
    if resp.tool_calls:
        obs = execute(resp.tool_calls)         # CAP/환율/그라운딩 실행
        append(obs)                            # 관찰 피드백
    else:
        done = True                            # 목표 달성

⚠️ Orchestration의 tool_call 응답/피드백 포맷은 스파이크(라이브)로 확정 후 고정. LangGraph node로 감쌀지, 핸드롤 루프로 둘지도 이때 결정.
