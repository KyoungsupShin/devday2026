# ERP·MDM 변경 영향 검토

## 목적

승인된 업무 변경이 ERP·MDM 데이터, 매핑, 검증, 추적성과 롤백에 미치는 영향을 정리한다.

## 적용 범위

승인된 업무 변경의 데이터·시스템 통제 영향 검토에 적용한다. 시스템 반영, 변경 승인, 권한 부여와 데이터 입력은 별도 절차에 따른다.

## Stakeholder

| 역할 | 책임 |
| --- | --- |
| IT팀 | 데이터 영향, 식별자·필드 매핑, 검증·추적·롤백 조건을 검토한다. |
| 업무 변경 책임자 | 독립적으로 확인된 업무 변경 근거와 대상 범위를 제공한다. |
| 권한 있는 사람 | 공식 변경 결정을 별도 권한 체계에 따라 수행한다. |

## 프로세스

1. 승인되었거나 독립 근거가 있는 업무 변경의 대상과 범위를 확인한다.
2. 대상 데이터, 식별자, 필드 매핑과 변경 전제조건을 확인한다.
3. 검증, 감사 추적과 롤백에 필요한 근거를 정리한다.
4. 미확정 데이터와 확인 질문을 변경 책임자에게 인계한다.
5. 공식 변경 절차에 필요한 입력과 실행 경계를 기록한다.

## 단계별 인계 기준

1. **업무 변경 책임자 → IT팀:** 승인 상태, 변경 목적·적용 범위, 대상 마스터·트랜잭션 식별자, 변경 전후 값과 업무 영향 근거를 전달한다. 승인되지 않았거나 근거가 불충분한 변경은 IT 검토의 입력이 아니다.
2. **IT팀 → 업무 변경 책임자:** 필드·코드 매핑, 참조 데이터, 인터페이스·권한 영향, 검증·감사 추적·롤백 요구사항과 누락 정보를 회신한다.
3. **IT팀 → 권한 있는 사람:** 통제·검증 조건과 잔여 위험을 정리해 공식 변경 실행 절차로 인계한다. IT팀은 이 검토만으로 데이터를 쓰거나 권한을 부여하지 않는다.

## 확인 사항과 산출물

- 확인 사항: 업무 변경 근거, 승인 상태, 데이터·식별자, 매핑, 검증, 추적성, 롤백
- 산출물: 변경 영향 검토 기록, 공식 변경 절차 입력

## 실행 경계

영향 검토는 ERP·MDM 시스템 변경을 직접 수행하거나 변경 완료를 보장하지 않는다.
