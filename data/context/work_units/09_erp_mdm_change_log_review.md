# ERP·MDM 변경 기록 점검

## 목적

승인된 변경의 데이터 매핑, 검증, 추적성과 롤백 기록을 점검해 변경 통제의 누락을 식별한다.

## 적용 범위

주간 또는 월간 ERP·MDM 변경 기록 점검에 적용한다. 실제 시스템 반영, 권한 부여와 변경 승인은 포함하지 않는다.

## Stakeholder

| 역할 | 책임 |
| --- | --- |
| IT팀 | 변경 대상, 승인 근거, 식별자, 매핑·검증·추적 기록을 점검한다. |
| 변경 책임자 | 업무 변경 근거와 필요한 변경 기록을 제공한다. |
| 권한 있는 사람 | 공식 변경 승인과 실행 여부를 별도 절차에 따라 결정한다. |

## 프로세스

1. 기간별 변경 대상과 적용 범위를 확인한다.
2. 승인 상태, 식별자, 데이터 매핑과 검증 기록을 확인한다.
3. 추적성·롤백 기록의 누락과 데이터 시점 차이를 분류한다.
4. 누락 항목과 확인 질문을 변경 책임자에게 전달한다.
5. 결과, 기한, 담당자와 공식 승인 여부를 분리해 기록한다.

## 단계별 인계 기준

1. **변경 책임자 → IT팀:** 승인 또는 검토 근거, 업무 대상·범위, 데이터 식별자, 변경 전후 값·매핑과 적용 예정 시점을 전달한다.
2. **IT팀 → 변경 책임자:** 누락된 승인, 식별자·매핑 오류, 검증·감사 추적·롤백 증빙 부족을 구분해 회신하고 보완 질문을 명시한다.
3. **IT팀 → 권한 있는 사람:** 통제 검토가 끝나도 실제 반영은 하지 않으며, 실행 승인·권한 부여가 필요한 경우 검토 결과와 잔여 위험을 별도 절차로 인계한다.

## 확인 사항과 산출물

- 확인 사항: 변경 근거, 승인 상태, 식별자, 매핑, 검증, 추적성, 롤백
- 산출물: 변경 통제 점검 기록, 누락 목록

## 실행 경계

기록 점검은 시스템 변경 완료, 권한 부여 또는 업무 변경 승인을 뜻하지 않는다.
