# 부서 간 협업 SOP

## 목적과 적용 범위

이 문서는 A2A 협업에서 요청을 검토·인계하는 일반 원칙을 설명한다. 공식 ERP 조회, 구매 실행, 예산 승인, 공급처 확정 또는 시스템 변경은 각 조직의 최신 권한 체계와 운영 규정에 따라 별도로 수행한다.

## 프로세스

1. 요청 접수
   - 요청 부서, 업무 대상, 요청 목적과 현재 관찰 사실을 구분해 기록한다.
   - 제공되지 않은 사양, 재고, 단가, 예산, 승인 상태는 추정하지 않고 추가 확인 항목으로 남긴다.

2. 현장 작업자 구매 요청의 설비 확인 선행
   - 현장 작업자가 설비·설비 부품·유지보수와 관련된 구매를 요청한 경우, 구매팀이 바로 조달 검토를 시작하지 않는다.
   - 먼저 설비팀 엔지니어가 현장 관찰 내용, 대상 식별, 운전 영향, 안전·기술상 제약과 필요한 기술 확인 사항을 검토한다.
   - 다음으로 설비팀 관리자가 엔지니어 검토 결과를 확인해 요청의 업무 목적, 우선순위, 추가 현장 확인 필요 여부와 구매 검토로 넘길 수 있는 범위를 판단한다.
   - 엔지니어 검토와 관리자 확인의 근거가 누적된 뒤에만 구매팀이 기준정보, 재고·수급, 공급 조건, 구매 요청 상태 등을 검토한다.
   - 이 순서는 검토와 근거 축적의 기준이며, 승인 또는 구매 실행 자체를 뜻하지 않는다.

3. 관련 부서 협업
   - 구매팀은 조달 가능성 및 기준정보·재고 등 제공된 조회 근거를 검토한다.
   - 제조기획팀은 생산계획, 투입 준비, 라인 또는 운영 영향이 필요한 경우 검토한다.
   - 재무·사업기획팀은 예산, 원가, 수익성 또는 이관 검토가 필요한 경우 근거와 한계를 구분한다.
   - IT팀은 승인된 변경이 ERP·MDM 데이터나 변경 통제에 미치는 영향을 검토한다.
   - Orchestration Agent는 누적 근거와 미해결 판단을 관찰해 다음 검토를 요청하거나, 사람의 명시적 판단이 필요한 지점을 안내한다. 특정 팀·순서를 코드로 고정하지 않는다.

4. 결과 정리 및 사람 확인
   - 확인된 근거, 미확정 항목, 다음 조치를 구분해 요청 부서에 전달한다.
   - 공식 제출, 예산 배정, 승인, 외부 발송 또는 시스템 쓰기가 필요하면 권한 있는 사람이 검토·결정한다.

## Stakeholder와 책임

| 역할 | 책임 |
| --- | --- |
| 현장 작업자 | 관찰된 현상과 업무 필요를 요청으로 전달한다. |
| 설비팀 엔지니어 | 기술적 관찰, 대상 식별, 운전·안전 영향 및 추가 확인 항목을 검토한다. |
| 설비팀 관리자 | 엔지니어 검토를 확인하고 요청의 우선순위와 후속 협업 범위를 판단한다. |
| 구매팀 | 설비팀 확인 이후 조달·기준정보·재고·수급 관련 근거를 검토한다. |
| 제조기획·재무·IT팀 | 요청에 실제로 관련된 생산, 재무, 데이터·변경 통제 관점을 근거 범위 내에서 검토한다. |
| 권한 있는 사람 | 승인, 공식 제출, 외부 발송 및 시스템 쓰기를 명시적으로 결정한다. |

## 확인해야 할 사항

- 요청 주체와 요청 대상, 현장 관찰 사실
- 현장 작업자 요청인지와 설비·유지보수 관련성
- 설비팀 엔지니어의 기술 검토 및 설비팀 관리자의 확인 여부
- 기준정보, 재고·수급, 공급·견적, 생산·품질, 예산·원가, ERP·MDM 변경 중 실제로 필요한 검토 범위
- 제공된 데이터의 시점·상태·적용 범위와 미확정 정보
- 사람의 승인·제출·외부 실행이 필요한 지점

## 데이터와 실행 경계

이 SOP는 검토 기준을 제공한다. Agent가 읽는 로컬 스냅샷은 해당 시점에 적재된 기록이며, 최신 운영 상태 또는 실행 완료를 보장하지 않는다. 어떤 Agent도 이 문서만으로 외부 시스템을 변경하거나 구매·승인을 완료할 수 없다.
