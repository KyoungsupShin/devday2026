# 부서 간 협업 역할과 책임 운영기준

## 목적과 적용 범위

이 문서는 부서 간 협업 SOP를 보완하기 위해 요청 접수, 검토, 인계와 최종 확인 과정에서 각 역할이 제공해야 할 근거와 결과물을 정의한다. 설비·설비 부품·유지보수 구매 요청에는 SOP에 따른 설비팀 → 구매팀 → 제조기획팀의 검토 순서를 적용한다.

이 문서는 검토 기준이다. 공식 ERP 조회, 구매 실행, 예산 배정·승인, 공급처 확정, 시스템 변경, 공식 제출 또는 외부 발송 권한을 부여하지 않는다. 해당 행위는 각 조직의 최신 권한 체계와 운영 규정에 따라 권한 있는 사람이 별도로 결정한다.

## 공통 협업 원칙

- 요청 대상, 목적, 관찰 사실과 요청자의 기대 결과를 구분해 기록한다.
- 사양, 재고, 단가, 예산, 승인 상태, 시스템 상태처럼 제공되지 않은 정보는 추정하지 않고 미확정 확인 항목으로 남긴다.
- 각 부서는 자기 책임 범위의 근거와 한계를 제시한다. 다른 부서의 승인, 확정 또는 실행 결과를 대신 판단하지 않는다.
- 설비·구매·제조기획의 선행 검토가 필요한 요청은 세 부서의 근거와 미확정 항목을 누적한 뒤에만 결과를 정리하고 최종 확인으로 넘긴다.
- 기록 또는 로컬 스냅샷은 해당 시점과 범위의 근거이며, 최신 운영 상태나 실행 완료를 뜻하지 않는다.

## 공통 인계 형식

각 인계에는 다음 정보를 포함한다.

1. **요청 대상과 관찰 사실**: 대상 식별자, 요청 목적, 확인된 현상 및 적용 범위
2. **확인된 근거와 출처 범위**: 검토한 기록, 문서, 데이터의 시점과 적용 범위
3. **미확정 항목과 질문**: 결론을 위해 추가로 필요한 입력, 확인 주체 및 이유
4. **검토 결과와 다음 인계**: 책임 범위 안의 검토 결과, 다음 검토 부서 및 인계 조건
5. **승인 여부의 분리**: 검토 결과나 권고와 승인·확정·실행 여부를 분리해 표시

## 역할별 책임과 인계 기준

### 현장 작업자

**목적과 책임**

- 업무 필요, 관찰된 현상, 요청 대상과 현장 영향 정보를 요청으로 전달한다.
- 안전상 즉시 공유가 필요한 사실과 현재 적용 중인 임시 조치를 사실 범위에서 기록한다.

**담당하지 않는 판단**

- 기술 사양 확정, 구매 승인, 공급처 선정, 예산 배정, 생산계획 변경 또는 시스템 변경을 결정하지 않는다.

**검토 시작에 필요한 입력**

- 요청 대상과 위치 또는 식별 정보, 관찰 시점, 현상, 업무 영향, 이미 확인한 사실

**결과물과 인계 조건**

- 설비·설비 부품·유지보수 관련 요청은 설비팀이 검토할 수 있도록 관찰 사실과 대상 식별 정보를 인계한다.
- 정보가 부족하면 추정 대신 추가 확인이 필요한 항목을 명시한다.

### 설비팀

**목적과 책임**

- 현장 관찰, 대상 식별, 운전 영향, 안전·기술상 제약 및 필요한 기술 확인 사항을 검토한다.
- 설비·부품·유지보수 요청의 기술적 범위와 조달 검토에 필요한 사양 또는 확인 질문을 정리한다.

**담당하지 않는 판단**

- 공급처 확정, 구매 승인, 예산 배정, 생산계획 확정 및 ERP 변경을 결정하지 않는다.

**검토 시작에 필요한 입력**

- 현장 작업자의 관찰 사실, 설비 또는 부품 식별 정보, 현장 영향, 알려진 안전 조건

**결과물과 인계 조건**

- 기술 관찰, 대상 식별, 운전·안전 영향, 기술 제약과 미확정 사양을 기록한다.
- 설비·부품·유지보수 구매 요청은 이 결과를 근거로 구매팀에 인계한다. 기술 입력이 부족하면 미확정 항목으로 남기며 승인 요청으로 전환하지 않는다.

### 구매팀

**목적과 책임**

- 설비팀의 검토 근거를 바탕으로 기준정보, 재고·수급, 공급 조건과 구매 요청 상태를 검토한다.
- 조달 측면에서 확인된 근거, 제한 사항 및 추가 확인이 필요한 항목을 구분한다.

**담당하지 않는 판단**

- 설비 기술 적합성, 생산 투입 승인, 예산 승인, 품질 승인 또는 시스템 변경을 결정하지 않는다.

**검토 시작에 필요한 입력**

- 설비팀의 대상 식별과 기술 제약, 필요한 사양, 현장 영향, 기존 구매 요청 또는 공급 관련 기록

**결과물과 인계 조건**

- 기준정보, 재고·수급, 공급 조건, 구매 요청 상태의 근거와 한계를 기록한다.
- 설비·부품·유지보수 구매 요청은 이 결과와 미확정 항목을 제조기획팀에 인계한다.

### 제조기획팀

**목적과 책임**

- 구매팀 검토 근거를 바탕으로 생산계획, 자재·투입 준비도, 라인 또는 운영 영향과 필요한 확인 사항을 검토한다.
- 생산 운영 관점에서 준비 상태와 계획상 제약을 구분해 정리한다.

**담당하지 않는 판단**

- 구매 실행, 공급처 확정, 예산 승인, 설비 수리 승인, 품질 release 또는 ERP 변경을 결정하지 않는다.

**검토 시작에 필요한 입력**

- 설비팀의 기술 검토 결과, 구매팀의 기준정보·재고·수급·공급 조건 검토 결과, 요청 대상과 필요한 시점

**결과물과 인계 조건**

- 생산계획, 자재·투입 준비도, 라인·운영 영향, 미확정 확인 사항을 기록한다.
- 설비팀·구매팀·제조기획팀의 근거가 모두 누적되면 요청 부서에 검토 결과와 미확정 항목을 전달하고, 승인이나 실행이 필요할 경우 권한 있는 사람의 최종 확인으로 인계한다.

### 재무팀

**목적과 책임**

- 예산 여력, 원가, 비용 귀속, 예산 이관 또는 관리회계 관점에서 제공된 근거와 한계를 검토한다.
- 검토 대상의 재무 정보와 미확정 재무 입력을 구분한다.

**담당하지 않는 판단**

- 기술 사양, 공급처 선정, 생산 실행, 품질 판정 또는 시스템 변경을 결정하지 않는다. 예산 배정과 승인 자체도 권한 있는 사람의 결정 대상이다.

**검토 시작에 필요한 입력**

- 요청의 비용 또는 예산 관련 목적, 대상과 기간, 제공된 원가·예산·비용 귀속 근거, 필요한 승인 또는 이관 정보

**결과물과 인계 조건**

- 예산·원가·비용 귀속 관점의 확인 결과, 한계 및 추가 확인 항목을 기록한다.
- 사업성·수익성 관점의 별도 검토가 필요하면 해당 목적과 필요한 입력을 사업기획팀에 인계한다. 승인 또는 배정이 필요하면 검토 근거를 권한 있는 사람에게 전달한다.

### 사업기획팀

**목적과 책임**

- 수익성, 사업성, 계획 가정과 운영 영향의 관점에서 제공된 근거를 검토한다.
- 재무팀의 예산·원가 통제 관점과 구분해 사업성 판단에 필요한 가정과 불확실성을 정리한다.

**담당하지 않는 판단**

- 예산 승인, 회계 처리, 기술 사양 확정, 구매 실행, 품질 승인 또는 시스템 변경을 결정하지 않는다.

**검토 시작에 필요한 입력**

- 요청의 사업 목적, 계획 기간, 수요·수익·원가 또는 운영 영향에 관한 제공된 근거, 재무팀 검토 결과가 있는 경우 그 범위

**결과물과 인계 조건**

- 사업성·수익성 관점의 가정, 근거, 불확실성 및 추가 확인 항목을 기록한다.
- 예산 또는 비용 귀속 검토가 필요한 경우 재무팀에, 공식 승인이나 실행 판단이 필요한 경우 권한 있는 사람에게 근거를 인계한다.

### IT팀

**목적과 책임**

- 승인된 업무 변경이 ERP·MDM 데이터, 필드 매핑, 검증, 추적성 및 변경 통제에 미치는 영향을 검토한다.
- 변경 전제조건, 필요한 식별자, 검증·감사 추적과 롤백 관점의 확인 항목을 정리한다.

**담당하지 않는 판단**

- 업무·품질·조달·예산 승인 자체를 재검토하거나 결정하지 않는다. 승인 전 업무 변경을 시스템에 반영하지 않는다.

**검토 시작에 필요한 입력**

- 독립적으로 확인된 업무 변경 근거, 관련 승인 또는 최종 결정 상태, 대상 데이터와 식별자, 필요한 변경 범위

**결과물과 인계 조건**

- 데이터 매핑, 검증 전제조건, 변경 추적성과 롤백에 필요한 근거 및 미확정 항목을 기록한다.
- 권한 있는 사람이 업무 변경을 최종 결정한 뒤에만 공식 변경 절차의 입력으로 사용한다.

### 권한 있는 사람

**목적과 책임**

- 누적된 검토 근거와 미확정 항목을 바탕으로 공식 제출, 예산 배정, 승인, 외부 발송 또는 시스템 쓰기 여부를 최종 결정한다.

**담당하지 않는 판단**

- 각 전문 부서가 제공해야 할 기술·조달·생산·재무·사업성·데이터 변경 근거를 대신 만들어 내지 않는다.

**검토 시작에 필요한 입력**

- 적용된 선행 검토 결과, 출처와 범위, 미확정 항목, 필요한 결정의 종류와 영향

**결과물과 인계 조건**

- 최종 결정과 조건을 공식 절차에 따라 기록한다. 실제 실행은 결정된 권한과 별도 운영 절차에 따라 수행한다.

## 요청 유형별 상세 절차

### 설비·설비 부품·유지보수 구매 요청

1. 현장 작업자는 대상, 관찰 사실, 현장 영향과 알려진 안전 조건을 기록한다.
2. 설비팀은 기술 관찰, 대상 식별, 운전·안전 영향, 제약 및 필요한 기술 입력을 검토한다.
3. 구매팀은 설비팀 근거를 바탕으로 기준정보, 재고·수급, 공급 조건과 구매 요청 상태를 검토한다.
4. 제조기획팀은 앞선 검토 결과를 바탕으로 생산계획, 자재·투입 준비도, 라인·운영 영향을 검토한다.
5. 세 부서의 근거와 미확정 항목이 누적된 뒤 요청 부서에 결과를 전달한다. 공식 구매나 승인이 필요한 경우 권한 있는 사람이 최종 결정한다.

### 예산·원가·수익성 검토 요청

1. 요청 부서는 대상, 기간, 사업 목적과 제공 가능한 비용·예산·계획 근거를 정리한다.
2. 재무팀은 예산, 원가, 비용 귀속, 예산 이관 또는 관리회계 관점을 검토한다.
3. 사업기획팀은 수익성, 사업성, 계획 가정과 운영 영향을 별도 관점에서 검토한다.
4. 두 부서의 근거와 한계는 분리해 기록하며, 어느 검토도 예산 배정이나 승인 자체를 뜻하지 않는다.
5. 승인 또는 공식 결정이 필요하면 권한 있는 사람에게 누적 근거를 인계한다.

### 승인된 업무 변경의 ERP·MDM 영향 검토

1. 요청 부서는 독립적으로 확인된 업무 변경 근거와 적용 대상, 관련 승인 또는 결정 상태를 제공한다.
2. IT팀은 ERP·MDM 데이터 영향, 필드 매핑, 검증 전제조건, 변경 추적성과 롤백 근거를 검토한다.
3. IT팀의 결과는 변경 준비 상태와 확인 항목을 나타내며, 시스템 변경 완료나 승인으로 해석하지 않는다.
4. 최종 결정 후 실제 시스템 반영은 권한과 별도 변경 절차에 따라 수행한다.

### 최종 승인 및 외부 실행

1. 요청 부서는 적용된 각 부서의 검토 근거, 출처 범위, 미확정 항목과 필요한 결정을 함께 제시한다.
2. 권한 있는 사람은 공식 제출, 예산 배정, 승인, 외부 발송 또는 시스템 쓰기 여부를 최종 결정한다.
3. 결정 이후의 실행은 조직의 권한 체계와 운영 규정에 따라 별도로 수행하며, 이 문서의 검토 결과만으로 실행하지 않는다.

## 데이터와 실행 경계

이 문서는 부서 간 협업의 역할과 인계 기준을 제공한다. 문서에 기록된 검토 결과, 로컬 스냅샷 또는 개별 기록은 그 출처와 시점의 범위 안에서만 해석한다. 어떤 역할도 이 문서만으로 외부 시스템을 변경하거나 구매·승인·예산 배정·공식 제출을 완료할 수 없다.
