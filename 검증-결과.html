1. 검증 목적

참가자가 복붙·실행할 코드가 이 테넌트에서 실제로 동작하는지, 그리고 강사의 사전 수집(저장소 생성)과 사후 정리(삭제) 까지 문제없이 돌아가는지 확인한다. 워크숍 당일 "코드는 맞는데 환경에서 안 돈다"를 사전에 제거하는 것이 목표.

2. 검증 방법

validate_handson.py 스크립트 1개로 lifecycle 전체를 실제 AI Core에 호출해 수행했다.

[1단계 생성]  그라운딩 벡터 저장소 생성 + documents/ PDF 수집
[2단계 검증]  모듈 1~6(+보조 3b, 출력필터, 스트리밍) 실제 호출
[3단계 삭제]  생성한 저장소 자동 삭제 (finally 보장 — 실패해도 정리됨)
  • 라이브: 실제 orchestration 배포·모델·그라운딩 API에 호출 (모킹 없음)
  • 환경: 참가자와 동일한 SDK(codejam 고정본 sap-ai-sdk-gen==5.11.0), Python 3.13
  • 판정: 응답 내용까지 확인 (예: 마스킹은 MASKED_* 포함, 메모리는 이름 회상 여부)

5. 특이사항 (코드에 반영 완료)

  • gpt-5.6-sol 은 temperature=0 미지원(GPT-5 계열 제약) → orchestration 코드에서 temperature 제거(기본값), 모듈 1 온도 실험은 0.2 vs 1.5 로 조정, 트러블슈팅에 항목 추가. temperature=0 결정론 데모가 필요하면 gpt-4.1 등으로.
  • gpt-4o-mini, gemini 계열은 이 테넌트에 미배포 → 예제·실험 모델명을 배포된 이름(gpt-5.6-sol, anthropic--claude-4.6-sonnet 등)으로 정리.
  • 멀티모달은 gpt-5.6-sol 로 동작 확인.
  • Orchestration은 기존 배포 사용, 그라운딩 저장소만 검증용으로 생성·삭제 → 잔존 리소스 없음.

6. 재현 방법

강사가 동일 검증을 다시 돌리려면:
