# 모듈 6 · 메모리 챗봇 (강사용)

🎯 **목표**: 대화 history 전달로 "기억하는" 챗봇 구현 + 지금까지 배운 것 종합.
⏱️ **시간**: 20분 (설명 7분 + 실습 13분) — 시간이 밀리면 강사 데모로 축약 가능
📓 기반: `10-chatbot-with-memory.ipynb`

---

## 🧑‍🏫 강사 노트 — 종합 모듈

여기서 Orchestration이 다시 등장합니다(모듈 3·4). 새 개념은 **history(대화 누적)** 하나뿐이라, 참가자가 "아 이제 이 패턴이 익숙하다"를 느끼게 하는 통합 단계입니다.

핵심: **LLM은 상태가 없다(stateless).** 매 호출은 독립적입니다. 그래서 "기억"하려면 **이전 대화를 매번 함께 보내야** 합니다. `history` 가 바로 그 누적 대화입니다.

💬 **이렇게 말하세요**: "모델은 금붕어예요 — 매번 처음 봅니다. '기억'은 사실 우리가 지난 대화를 매 호출마다 다시 넣어주는 거예요. ChatGPT도 내부적으로 이렇게 합니다."

## 코드 설명 포인트

🧑‍🏫 `chat()` 메서드의 세 줄이 핵심:
1. `history=self.history` — 이전 대화를 함께 전달
2. `self.history = response.intermediate_results.templating` — 서버가 구성한 메시지 목록(히스토리)으로 갱신
3. `self.history.append(message)` — 이번 모델 답변도 히스토리에 추가

즉 매 턴마다 history가 user/assistant 쌍으로 쌓이고, 다음 호출에 전부 실려 갑니다.

🎬 **라이브 데모 (효과 확실)**:
1. "Hello" → "Do you like SAP CodeJams?" → "Can you remember what we first talked about?" 순서로 호출. 마지막에 "Hello였다"고 답하면 메모리 작동.
2. `bot.history` 를 출력해 쌓인 대화를 눈으로 확인.
3. `bot.reset()` 후 같은 질문 → 이제 기억 못 함. "메모리를 비웠으니 금붕어로 돌아간 거죠."

## 직접 바꿔보기 (실험)

- reset 전후 비교 (위 데모를 참가자가 직접)
- 페르소나 변경 (system 프롬프트)
- ⭐ **종합 과제**: 모듈 4의 그라운딩 config를 이 ChatBot의 `config` 에 넣어 **"기억 + 근거"** 챗봇 완성. 오늘 배운 모듈 조합의 정점. 시간 되면 꼭 시도.

## ❓ 예상 질문 & 답

- **"history가 무한정 쌓이면?"** → 토큰 한계·비용↑. 실무에선 오래된 대화 요약·윈도우 제한·중요 정보만 추출 등 메모리 관리 전략 사용.
- **"세션별로 분리하려면?"** → ChatBot 인스턴스를 사용자/세션마다 하나씩, 또는 history를 외부 저장소(DB)에 세션 키로 보관.
- **"그라운딩이랑 같이 쓰면 history에 context도 쌓이나요?"** → 설계에 따라. 보통 질문/답변만 history로, context는 매 턴 새로 검색.

## ⚠️ 흔한 실수

- `history=self.history` 를 안 넘김 → 매번 "기억 못 하는" 봇. "왜 기억을 못 하죠?"로 디버깅 유도.
- history 갱신 로직 누락 → 대화가 안 쌓임.
- 모델명 미지정(`name=""`) → 노트북 원본은 비어 있으니 배포된 모델명을 넣게.
