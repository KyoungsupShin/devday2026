⌂ 인덱스강사용 / 02-임베딩-유사도

모듈 2 · 임베딩 & 벡터 유사도 (강사용)

🎯 목표: 임베딩 = 의미의 숫자화, 유사도 = RAG 검색의 원리임을 체감. ⏱️ 시간: 30분 (설명 10분 + 실습 20분) 📓 기반: 04-create-embeddings.ipynb

🧑‍🏫 강사 노트 — 수학 깊이 조절이 관건

청중 수준에 따라 설명 깊이를 조절하세요.

  • 비전공/업무 청중: "임베딩 = 문장의 의미를 좌표로 찍은 것. 가까우면 비슷한 뜻." 수식 생략. 2D 비유(지도 위의 점)로 충분.
  • 개발자 청중: 1536차원, 코사인 유사도 = 벡터 사이 각도의 코사인(1=동일 방향, 0=무관, -1=반대). 거리(distance)와 유사도(1-distance)의 관계.

💬 이렇게 말하세요: "모듈 1에서 '관련 문서를 찾아 넣으면 환각이 준다'고 했죠. 그럼 '관련'을 기계가 어떻게 알까요? 모든 텍스트를 숫자 벡터로 바꾼 다음, 질문 벡터와 가까운 문서 벡터를 찾는 겁니다. 그 '가까움'을 지금 계산해 봅니다."

1. 임베딩 생성

🧑‍🏫 embeddings.create(input=..., model_name=...) → response.data[0].embedding 이 벡터(리스트). 차원 수를 len() 으로 찍어 1536을 보여주세요. "이 1536개 숫자가 'apple'의 의미 좌표"라고.

2. 코사인 유사도 — 의도된 버그 (교육용 하이라이트)

🎬 이 부분은 일부러 틀린 코드를 참가자가 고치게 하는 설계입니다. 함수가 vector_1 을 두 번 넘겨서 항상 1.0(자기 자신과의 유사도) 을 반환합니다.

진행법: 1. 버그 버전으로 apple–orange를 계산 → 1.0이 나옴 2. "사과와 오렌지가 100% 똑같다고요? 뭔가 이상하죠" 라고 질문 던지기 3. 참가자가 vector_1, vector_1 → vector_1, vector_2 를 스스로 찾게 4. 고친 뒤 다시 실행 → 1.0보다 작은 현실적인 값

🧑‍🏫 이 장치는 "AI 코드도 틀린다 / 출력을 비판적으로 보라"는 교훈을 자연스럽게 줍니다. vibe coding 시대에 특히 중요한 태도 — 뒤의 보너스(Copilot) 팁과 연결하세요.

3. 유사도 비교 해석

🧑‍🏫 기대 결과: apple–orange > apple–phone, dog–animals > dog–cat. 단, 임베딩 모델에 따라 "I hate cats"와 "I love dogs"도 (둘 다 동물·감정 문장이라) 생각보다 높게 나올 수 있음 — "유사도는 '주제 유사'지 '감정 일치'가 아니다"를 설명할 좋은 기회.

직접 바꿔보기 (실험)

  • 참가자 본인 도메인 단어로 유사도 매트릭스 (실무 연결)
  • 다국어 유사도("dog" vs "개") → 다국어 임베딩의 힘
  • 문장 vs 단어

❓ 예상 질문 & 답

  • "1536차원을 어떻게 상상하나요?" → 상상 못 해도 됨. 수학은 2D와 똑같이 작동. 중요한 건 "가까움"의 상대비교.
  • "임베딩은 어디 저장하나요?" → 지금은 메모리 변수. 실무에선 벡터 저장소에 저장 — 모듈 5에서 AI Core가 관리하는 벡터 저장소(Document Grounding)에 문서를 넣고 검색합니다. (직접 운영하려면 HANA Vector Engine 등도 선택지)
  • "유사도 임계값은 얼마로?" → 절대값보다 상대순위가 중요. RAG에선 보통 top-k(가장 가까운 k개)를 뽑음(모듈 6의 search_kwargs={"k": 2}).

⚠️ 흔한 실수

  • 버그를 못 찾고 넘어감 → 결과가 전부 1.0. "왜 다 1이 나올까요?"로 유도.
  • 임베딩 배포 ID/모델명 오류 → 모듈 0의 EMBEDDING_DEPLOYMENT_ID 확인.
